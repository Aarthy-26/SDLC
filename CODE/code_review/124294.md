Findings:
Issue: Broad catch block in initialize() swallows the underlying error cause, reducing diagnosability and audit usefulness.
Severity: Medium
Recommendation: Capture the error as unknown, narrow it safely, and log or emit a sanitized reason code rather than dropping context entirely.
Compliance Impact: SOC2 traceability is weaker when operational failures are not captured with adequate diagnostic context.

Issue: handleCallback() clears the PKCE record only after a successful code exchange. On failed exchange, stale PKCE state may remain in sessionStorage until timeout.
Severity: Medium
Recommendation: Wrap the exchange step in try/finally and clear the PKCE record in finally, or clear on both success and failure paths.
Compliance Impact: Low direct compliance impact, but stale auth state can complicate auditability and user support.

Issue: No explicit validation of requested redirect path before redirectAfterLogin(), allowing open-redirect risk if an attacker can influence redirect or stored requestedPath with an absolute/external URL.
Severity: High
Recommendation: Restrict redirect targets to relative in-app paths only. Reject absolute URLs and normalize to '/'.
Compliance Impact: Security control gap affecting secure authentication flow; relevant to SOC2 secure access controls.

Issue: buildProvisioningAuditPayload() includes email, name, uniqueId, groups, and roles in browser event detail. Depending on listeners, this may expose more identity data than necessary in the client runtime.
Severity: Medium
Recommendation: Minimize audit event payloads in the browser and send authoritative audit events from the backend. Include opaque identifiers where possible instead of full PII.
Compliance Impact: GDPR/privacy minimization concern; potential overexposure of personal data in client-side telemetry.

Issue: fetchJson() throws generic errors without parsing structured server error responses, so user-facing handling cannot distinguish transient service failures from validation or access issues unless encoded in query params.
Severity: Medium
Recommendation: Parse safe error response bodies and map them to typed application errors for clearer UX and supportability.
Compliance Impact: Indirect SOC2 operational supportability impact; improves incident traceability.

Issue: No AbortController or mounted-state guard around async initialization, which can lead to state updates after unmount in edge navigation scenarios.
Severity: Low
Recommendation: Use AbortController for fetch requests or an isMounted pattern suitable for React hooks.
Compliance Impact: None significant.

Issue: Exported/public helper functions lack API documentation comments.
Severity: Low
Recommendation: Add concise TSDoc comments for auth helpers and DTOs, especially security-sensitive functions like createCodeChallenge(), readPkceRecord(), and fetchJson().
Compliance Impact: Internal maintainability standard only.

Issue: Session expiry timer is scheduled for the full remaining duration without resilience for clock skew or visibility changes.
Severity: Low
Recommendation: Add periodic session refresh/check or small skew buffer, and revalidate on tab focus.
Compliance Impact: Low; mainly robustness.
