Findings:
Issue: Feature-flag disabled path is implemented with `ResponseStatusException`, but the custom `AppCreationDisabledException` class is unused.
Severity: Low
Recommendation: Remove `AppCreationDisabledException` if not needed, or use a single domain-specific exception consistently with a centralized exception handler.
Compliance Impact: None direct; minor maintainability issue.

Issue: The code defaults to `orElse(true)` when the property is missing or blank, which may be unsafe for higher environments where creation should be disabled by policy.
Severity: Medium
Recommendation: Confirm business intent. If higher environments should fail closed, default to `false` when the property is absent, or require the property to be present and throw a server-side configuration error when missing.
Compliance Impact: Could weaken change-control and access governance expectations under SOC2 if a missing config unintentionally enables creation.

Issue: No audit logging is present for attempted app creation when the feature is disabled or when an app is successfully created.
Severity: Medium
Recommendation: Add structured audit logs using the approved Java logging framework (e.g., SLF4J) with actor, timestamp, outcome, and correlation/request ID. Avoid logging sensitive payload contents.
Compliance Impact: SOC2 traceability concern; sensitive operations should be auditable.

Severity: Low
