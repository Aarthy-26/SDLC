# RCA: Confluence Wiki – Test Connection is successful with a previously deleted Space Key, but saving the KB throws a 500 Internal Server Error instead of restricting the user during the Test Connection itself. (ADO #119652)

## 1. Executive Summary
A Confluence knowledge-base connection is reported as valid during Test Connection even when the supplied Space Key has already been deleted, but the later save operation fails with an internal server error. The strongest evidence from the ticket is the behavioral gap between the validation step and the persistence step; the code in this repository shows generic datasource test and save endpoints but no Confluence-specific Space Key validation, which indicates the actual defect likely sits in a downstream connector or starter dependency. The most likely root cause is that Test Connection validates only transport/authentication while save performs a deeper content or space lookup and lets the resulting exception escape as a 500. The recommended fix is to validate Space Key existence/authorization during Test Connection and to convert save-time upstream failures into a user-facing 4xx error if the invalid key still reaches persistence.

## 2. Impact
Users configuring Confluence Wiki KBs can receive a false-positive success signal during setup and only encounter failure when saving, which breaks the expected workflow and wastes setup effort. The immediate downstream effect is that KB creation/update is blocked for deleted or inaccessible Confluence spaces. The ticket does not provide environment, repro payload, stack trace, logs, comments, attachments, or linked fixes, so impact frequency and affected deployment scope cannot be confirmed from ADO alone.

## 3. Root Cause
**Confidence: Probable.** The most likely cause is missing or incomplete business validation for Confluence Space Key existence in the Test Connection flow, combined with unhandled save-time failures when the downstream Confluence operation resolves the deleted space. In this repository, `DataSourceConnectionController` and `ConnectionPropertyValueController` expose generic connection create/read flows, `ConnectionTestService` is only a JDBC-style test contract, and `ConnectionTestServiceImpl` validates JDBC connectivity rather than Confluence resources; there is no visible Confluence Wiki handler or Space Key check under `service/datasource` in the checked-in code. That makes it unlikely this repo itself contains the faulty Confluence validation logic, and more likely that the actual bug resides in the external datasource integration layer referenced by the project dependency `com.asc.aava:aava-datasource-spring-boot-starter:1.0.3` in `datapowerAI/pom.xml`.

Because the ticket contains no stack trace, no comments, no attachments, and no linked commits/PRs, the exact failing class/method and whether the 500 is thrown in this repository or in the external starter cannot be confirmed without runtime logs or connector source.

## 4. Contributing Factors
The repository's datasource APIs are generic and appear to rely on external connection-specific implementations, which increases the chance that connector-specific validation is inconsistent across test and save operations. Error handling is present at controller level in several datasource endpoints, but if the external connector throws a non-mapped runtime exception during save, it can still surface through the global handler as an internal error. The dependency on `aava-datasource-spring-boot-starter` suggests core datasource behavior may be outside this repo's visible code, making defects harder to localize and verify from this codebase alone.

## 5. Fix
- **Immediate:** In the save flow for Confluence Wiki KB creation/update, catch the upstream "space not found / deleted / unauthorized" exception and return a controlled 4xx validation error instead of a 500.
- **Permanent:** Move Confluence Space Key existence and access validation into the same logic invoked by Test Connection, so Test Connection fails for deleted spaces before the user can proceed to save. The validation should call the Confluence API for the specific Space Key, not just verify base URL/auth reachability.

## 6. Prevention
Add connector-level tests that distinguish between successful authentication and valid resource selection, including a case for deleted or inaccessible Confluence spaces. Add structured logging around external connector failures so save-time errors clearly show whether the failure is from invalid space resolution versus transport/auth issues. Add contract tests to ensure Test Connection and Save share the same resource-validation rules for connector-specific entities like Confluence Space Keys.
