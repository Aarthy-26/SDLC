## C. Code Quality & Maintainability
**Result: Mostly compliant for small utility, but correctness/robustness gaps exist**

### Findings
1) **C-NullSafety: null args array causes NPE**
- **Severity**: Medium
- **Location**: `DecommissionStatus.fromArgs(String[] args)`
- **Criterion**: C-NullSafety
- **Issue**:
  - `for (String arg : args)` will throw `NullPointerException` if `args` is null.
- **Remediation**:
  - Add `Objects.requireNonNull(args, "args")` or treat null as empty and fail fast.

2) **C-ExceptionHandling: silent parsing failures**
- **Severity**: Medium
- **Location**: `DecommissionStatus.fromArgs`
- **Criterion**: C-ExceptionHandling
- **Issue**:
  - Malformed tokens are ignored; unknown keys ignored; invalid boolean values treated as `false` (Boolean.parseBoolean default).
- **Remediation**:
  - Fail fast with explicit errors; consider a CLI parser (picocli) or implement strict parsing with diagnostics.

3) **C-MagicStrings: CLI keys are hardcoded**
- **Severity**: Low
- **Location**: `fromArgs` switch cases
- **Criterion**: C-CodeQuality (NoMagicStrings)
