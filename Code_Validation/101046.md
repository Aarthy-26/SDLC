### B. Security (OWASP Top 10 mapping — explicit checks)

#### B-Injection
- **Finding:** None.
- **Rationale:** No SQL/LDAP/OS command construction. HTTP JSON calls are built via structured payloads using Jackson.

#### B-BrokenAuthentication
- **Finding:** None in code regarding hardcoded credentials.
- **Rationale:** Uses AppRole credentials from environment variables.
- **Residual risk:** AppRole `secretId` is a sensitive credential; ensure external rotation and secure injection.

#### B-SensitiveDataExposure
1) **Issue:** Secret verification reads secret values back into memory.
- **Severity:** Medium
- **Location:** `DatabricksTokenSecretUpdater.main()` (verification via `vault.readSecret(config.secretPath())`)
- **Criterion:** **B-SensitiveDataExposure**
- **Why it matters:** KV read returns the full secret value. Even if not logged, it increases exposure surface (heap dumps, debugging, memory inspection, accidental future logging).
- **Remediation:** Replace value-read verification with metadata-only verification.
  - For Vault KV v2, prefer `GET /v1/<mount>/metadata/<path>`.
  - Implement `VaultClient.readSecretMetadata()` to validate existence/version without retrieving secret values.
  - If read-back is unavoidable, ensure immediate discard and avoid retaining values.

2) **Issue:** Vault error body echoed into exceptions/logs (even if truncated) may contain sensitive context.
- **Severity:** Medium
- **Location:** `VaultClient.postJson()` and `VaultClient.getJson()` → `sanitizeVaultError(respBody)`
- **Criterion:** **B-SensitiveDataExposure**
- **Remediation:** Parse error payload and allowlist safe fields (e.g., only `errors[]`), or replace with generic error + correlation id. Ensure debug logging disabled in production.

#### B-XXE
- **Finding:** Not applicable.
- **Rationale:** No XML parsing.

#### B-BrokenAccessControl
- **Finding:** Mostly out of scope for a CLI utility.
- **Rationale:** Access control enforced by Vault policies/roles, not in code.
- **Recommendation (non-issue note):** Document the required Vault policy: least-privilege write to one path; deny read where feasible.

#### B-SecurityMisconfiguration
1) **Issue:** Transport security not strictly enforced; `http://` is allowed.
- **Severity:** High
- **Location:** `VaultConfig.fromEnvironment()` scheme validation allows `http` and `https`.
- **Criterion:** **B-SecurityMisconfiguration**
- **Why it matters:** SOC2/ISO27001 typically require encryption in transit for secrets management traffic in non-dev environments. Allowing plaintext increases risk of token interception.
- **Remediation:** Enforce `https` only (at minimum for INT/prod).
  - Option: allow `http` only under an explicit dev flag (e.g., `ALLOW_INSECURE_HTTP=true`) and default to reject.
  - Ensure TLS 1.2+ and hostname verification is enabled (HttpClient defaults typically do, but be explicit in security docs).
  - If enterprise policy requires, support mTLS (client cert) or custom truststore.

2) **Issue:** Generic exception catch in `main` can hide root causes and may lead to insufficient operational signals.
- **Severity:** Medium
- **Location:** `DatabricksTokenSecretUpdater.main()` catch `(Exception e)`.
- **Criterion:** **B-SecurityMisconfiguration** (operational/security posture; also overlaps with monitoring)
- **Remediation:** Catch specific exceptions (`IllegalArgumentException`, `VaultClientException`) and emit sanitized structured error codes; keep unknown exceptions but include a correlation id.

#### B-XSS
- **Finding:** Not applicable (no web output generation).

#### B-InsecureDeserialization
- **Finding:** Low risk but present usage of JSON deserialization.
- **Location:** `VaultClient` uses Jackson `readValue` into `Map`.
- **Criterion:** **B-InsecureDeserialization** (checked explicitly)
- **Assessment:** Acceptable because:
  - No Java native serialization.
  - No Jackson polymorphic typing enabled.
- **Recommendation:** Consider configuring `ObjectMapper` with safe defaults (disable default typing—already not enabled; consider limiting features if corporate standard requires).

#### B-UsingComponentsWithKnownVulnerabilities
- **Finding:** No explicit vulnerable components identified from the provided versions.
- **Criterion:** **B-UsingComponentsWithKnownVulnerabilities**
- **Recommendation:** Run dependency scanning (e.g., OWASP Dependency-Check / Snyk) in CI because vulnerability status changes over time.

#### B-InsufficientLoggingMonitoring
1) **Issue:** No explicit audit/correlation id tying actions across logs.
- **Severity:** Low
- **Location:** `DatabricksTokenSecretUpdater.main()`
- **Criterion:** **B-InsufficientLoggingMonitoring**
