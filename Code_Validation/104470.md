## 2) Security Review (OWASP Top 10 mapped) (B)

### B-Injection
- **Status:** Not observed.
- No SQL/LDAP/OS command building. No `Runtime.exec`/`ProcessBuilder`.

### B-BrokenAuthentication
1. **Hardcoded bearer tokens in source**
   - **Severity:** High
   - **Location:** `104470.java` `tokenToUser = Map.of("builder-token", ...)`
   - **Criterion:** **B-BrokenAuthentication**
   - **Why it matters:** Hardcoded tokens are credential-like secrets; cannot be rotated centrally; risk of leakage and misuse.
   - **Remediation:**
     - Replace with real auth: JWT/OIDC validation and RBAC/ABAC; enforce token expiry.
     - If keeping simulation: load tokens from environment/secret manager; add rotation guidance.

2. **No token expiry / session controls**
   - **Severity:** High
   - **Location:** `authenticate()` and `tokenToUser` map
   - **Criterion:** **B-BrokenAuthentication**
   - **Remediation:** Use JWT with exp/iat/nbf validation or an identity provider.

### B-SensitiveDataExposure
3. **Potential sensitive exception details returned to clients**
   - **Severity:** High
   - **Location:** `AppsHandler.handle()` returns `exception` class and `message`; `handleRestore()` returns `details` from exception
   - **Criterion:** **B-SecurityMisconfiguration** / **B-SensitiveDataExposure**
   - **Remediation:**
     - Return generic message + correlationId/errorId.
     - Log full exception server-side only.

### B-XXE
- **Status:** Not applicable (no XML parsing).

### B-BrokenAccessControl
4. **Authorization is coarse-grained (no per-app authorization)**
   - **Severity:** Medium
   - **Location:** `UserContext.canRead()` / `canRestore()` ignore `appId`
   - **Criterion:** **B-BrokenAccessControl**
   - **Remediation:** Introduce per-app entitlements (e.g., app ownership or ACLs); enforce least privilege.

### B-SecurityMisconfiguration
5. **Verbose internal error payload** (see #3)
   - **Severity:** High
   - **Location:** `AppsHandler.handle()`
   - **Criterion:** **B-SecurityMisconfiguration**
   - **Remediation:** Remove internal exception class/message from API response.

### B-XSS
- **Status:** Not applicable for this backend-only JSON API. If consumed by a browser, ensure proper escaping on the frontend.

### B-InsecureDeserialization
- **Status:** Not observed (no `ObjectInputStream` usage).

### B-UsingComponentsWithKnownVulnerabilities
- **Status:** Not determinable from single-file code (no dependency manifest). JDK-only.

### B-InsufficientLoggingAndMonitoring
6. **Audit logs go to stdout and are not tamper-evident**
   - **Severity:** Medium
   - **Location:** `audit()` uses `System.out.println(...)`
   - **Criterion:** **B-InsufficientLoggingAndMonitoring**

## 3) Code Quality & Maintainability (C)

1. **C-NullSafety:**
   - **Severity:** Medium
   - **Location:** `handleGetVersions(HttpExchange ex, String appId)` and `handleRestore(..., String appId, String versionStr)`
   - **Issue:** `appId` is not validated; extremely long or malformed values could cause log pollution and unexpected behavior.
   - **Remediation:** Validate `appId` with allowlist regex (e.g., `^[a-zA-Z0-9_-]{1,64}$`) and reject invalid input (400).

2. **C-ExceptionHandling:** broad catch without classification
   - **Severity:** Medium
   - **Location:** `catch (Exception restoreFailure)` in `handleRestore` and `catch (Exception e)` in handler
   - **Criterion:** **C-ExceptionHandling**
   - **Remediation:** Catch specific exceptions; use custom exceptions for known failures; always log root cause server-side.

3. **C-ResourceManagement:**
   - **Status:** Pass
   - `sendJson()` uses try-with-resources for response body.

4. **C-CyclomaticComplexity:**
   - **Severity:** Medium
   - **Location:** `AppsHandler.handle()` and `handleRestore()` have multiple branches
   - **Criterion:** **C-CyclomaticComplexity**
   - **Assessment:** Likely near/over threshold for `handleRestore()` due to many guards.
   - **Remediation:** Extract validation/auth checks into helper methods or a small service layer to reduce complexity.

5. **C-DuplicateCode:**
   - **Severity:** Low
   - **Location:** repeated patterns `authenticate -> canRead/canRestore -> sendJson error`
   - **Criterion:** **C-DuplicateCode**
   - **Remediation:** Centralize auth and error response patterns.

6. **C-ThreadSafety/Concurrency:**
   - **Severity:** Medium
   - **Location:** `App.versionsByNumber` is `HashMap` inside a `ConcurrentHashMap` of apps; reads occur without per-app lock.
   - **Criterion:** **C-ResourceManagement** / **C-NullSafety** (operational safety) 
   - **Remediation:** Make `versionsByNumber` a `ConcurrentHashMap` or guard reads with the same per-app lock if writes are added later.

7. **C-MagicStrings:**
   - **Severity:** Low
   - **Location:** permission strings, path segments, error codes
   - **Criterion:** **C-MagicNumbersStrings**
   - **Remediation:** Extract constants/enums.
