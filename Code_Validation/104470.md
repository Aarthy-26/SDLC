## B. Security (OWASP Top 10 mapping)

### B-Injection
- **Finding**: No SQL/OS/LDAP injection vectors observed.
- **Notes**: No database calls, command execution, or dynamic query building.

### B-BrokenAuthentication
1) **Hardcoded bearer tokens / simplistic auth model**
- **Severity**: High
- **Location**: `Code_Output/104470.java` → `authorize(...)`
- **Criterion**: B-BrokenAuthentication
- **Details**: Tokens `admin-token` and `user-token` are hardcoded and treated as credentials. No expiry, rotation, signature validation, or revocation.
- **Remediation**:
  - Externalize token/credentials to configuration at minimum (env/secret store).
  - Prefer enterprise auth (OAuth2/JWT validation) with expiry and audience checks.

### B-SensitiveDataExposure
2) **Information leakage in HTTP 500 responses**
- **Severity**: High
- **Location**: `Code_Output/104470.java` → `AppsHandler.handle(...)` catch-all
- **Criterion**: B-SensitiveDataExposure
- **Details**: The handler returns exception class name and message in the JSON response:
  - `details.error = ex.getClass().getSimpleName()`
  - `details.details = ex.getMessage()`
  This can disclose implementation details and aid attackers.
- **Remediation**:
  - Return a generic message with an `errorId`/`correlationId`.
  - Log the full exception server-side only.

### B-XXE
- **Finding**: Not applicable (no XML parsing).

### B-BrokenAccessControl
- **Finding**: Partially mitigated.
- **Notes**: `RESTORE` requires role `ADMIN` (403 for user-token). This is correct for the simulation.
- **Gap**: Authorization model is token-string based; no identity proof.

### B-SecurityMisconfiguration
3) **Verbose operational information printed to stdout**
- **Severity**: Medium
- **Location**: `Code_Output/104470.java` → `start(...)`
- **Criterion**: B-SecurityMisconfiguration
- **Details**: Startup logs disclose compile/run commands and server URL via `System.out.println`. In production these should be controlled logging.
- **Remediation**: Use an approved logging framework and appropriate log level; avoid exposing operational hints in restricted environments.

### B-XSS
- **Finding**: Not applicable in server-side JSON responses unless consumed by browser without proper encoding.

### B-InsecureDeserialization
- **Finding**: Not applicable (no Java serialization usage).

### B-UsingComponentsWithKnownVulnerabilities
- **Finding**: Not determinable from single-file code (no dependency manifest). JDK-only.

### B-InsufficientLoggingMonitoring
4) **Audit logging is incomplete and not safe under concurrency**
- **Severity**: High
- **Location**: `Code_Output/104470.java` → `private final List<AuditEntry> auditLog = new ArrayList<>();`
- **Criterion**: B-InsufficientLoggingMonitoring
- **Details**:
  - `auditLog` is a non-thread-safe `ArrayList` mutated by concurrent request threads.
  - Can lead to lost/corrupted audit entries under load.
  - No correlation/request id stored.
- **Remediation**:
  - Replace with thread-safe structure (`Collections.synchronizedList`, `CopyOnWriteArrayList`, or `ConcurrentLinkedQueue`).
  - Add `requestId/correlationId` and include it in audit entry and response.
  - Consider durable sink (file/SIEM/DB) for SOC2-grade auditability.

## C. Code Quality & Maintainability

### Issues Found

1) **Non-thread-safe mutable shared state (auditLog)**
- **Severity**: High
- **Location**: `Code_Output/104470.java` → field `auditLog`
- **Criterion**: C-ResourceManagement (thread-safety / shared resource) & C-NullSafety (secondary)
- **Details**: Concurrent modifications to `ArrayList` can throw or corrupt state.
- **Remediation**: Use a concurrent collection; also consider bounded retention.

- **Severity**: Medium
- **Location**: `Code_Output/104470.java` → `AppsHandler.handle(...)`
- **Criterion**: C-MethodLength & C-CyclomaticComplexity
- **Details**:

  - While likely under the 50-line threshold, it mixes parsing, routing, and error handling.
