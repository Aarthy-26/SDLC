### B. Security (OWASP Top 10 mapping — explicit)

1. **B-Injection**
- **Severity:** Low (Not applicable)
- **Result:** No SQL/OS/LDAP query construction. No `Runtime.exec`, no JDBC.
- **Note:** Input is echoed back in JSON responses and may be used for log injection; see B-SensitiveDataExposure / C-InputValidation.

2. **B-BrokenAuthentication**
- **Severity:** High  
- **Location:** `AppVersionHistoryBackend.authenticate()`; authorization checks in `handleGetVersions()` / `handleRestore()`
- **Criterion:** B-BrokenAuthentication  
- **Issue:** Authentication is simulated via `X-User` header and roles are caller-controlled via `X-Roles`. This is **not a secure auth model** and enables privilege escalation (client can set `X-Roles: ADMIN`).
- **Remediation:** In a real service: use verified identity (JWT/OIDC, mTLS, session/token with expiry). Derive roles from verified claims or server-side lookup; do not trust client-supplied roles.

3. **B-SensitiveDataExposure**
- **Severity:** High  
- **Location:** `AppsHandler.handle()` catch-all → `error("ServerError", ... Map.of("exception", ..., "message", safeMsg(e)))`
- **Criterion:** B-SensitiveDataExposure  
- **Issue:** Response includes exception class and sanitized message. Even with truncation, this can reveal internals, error conditions, and implementation details.
- **Remediation:** Return a generic 5xx message to clients. Include a correlation/request id in response. Log exception details server-side only (secured logs).

4. **B-XXE**
- **Severity:** Low (Not applicable)
- **Result:** No XML parsing.

5. **B-BrokenAccessControl**
- **Severity:** High  
- **Location:** `canRestore(UserContext user)` and role checks based on `X-Roles`
- **Criterion:** B-BrokenAccessControl  
- **Issue:** Because roles are client-provided, restore authorization is bypassable.
- **Remediation:** Same as B-BrokenAuthentication; enforce server-side authorization.

6. **B-SecurityMisconfiguration**
- **Severity:** Medium  
- **Location:** `main()` uses `System.out.println` and prints endpoints; error responses include exception details
- **Criterion:** B-SecurityMisconfiguration  
- **Issue:** Verbose operational output and internal detail exposure.
- **Remediation:** Use an approved logging framework with configurable log levels; remove internal details from client responses.

7. **B-XSS**
- **Severity:** Medium  
- **Location:** Multiple `error(... Map.of("appId", appId, ...))` and other responses echo `appId`/`user` back.
- **Criterion:** B-XSS  
- **Issue:** While this is a JSON API, if responses are rendered unsafely in a browser/console, reflected user-controlled strings (appId/user) can contribute to XSS/injection in consuming UI.
- **Remediation:** Validate `appId` and header values (allowlist regex). Avoid reflecting raw user input; or ensure consumers HTML-escape.

8. **B-InsecureDeserialization**
- **Severity:** Low (Not applicable)
- **Result:** No Java native deserialization.

9. **B-UsingComponentsWithKnownVulnerabilities**
- **Severity:** Low (Not applicable)
- **Result:** Uses only JDK classes; no external dependencies listed.

10. **B-InsufficientLoggingMonitoring**
- **Severity:** Medium  
- **Location:** `audit()` usage only for restore operations; GET requests not audited
- **Criterion:** B-InsufficientLoggingMonitoring  
- **Issue:** Restore is audited (good) but lacks correlation id, source IP, request id, and does not audit access attempts consistently.
- **Remediation:** Add correlation id, actor, appId, version, client IP, auth context, and outcome. Consider append-only persistent audit store and retention.

### C. Code Quality & Maintainability

1. **C-CyclomaticComplexity**
- **Severity:** Medium  
- **Location:** `AppsHandler.handle()`; `AppsHandler.handleRestore()`
- **Criterion:** C-CyclomaticComplexity  
- **Issue:** Multiple nested branches (routing, method gating, parsing, auth, transactional restore, rollback).
- **Remediation:** Refactor routing into smaller helpers (`parseRoute`, `validateMethod`, `parseVersionNumber`). Apply guard clauses and extract repeated responses.

2. **C-MethodLength**
- **Severity:** Medium  
- **Location:** `AppsHandler.handle()` and `handleRestore()`
- **Criterion:** C-MethodLength  
- **Issue:** Methods are long and do multiple responsibilities.
- **Remediation:** Break into smaller methods and reuse common response helpers.

3. **C-NamingConventions**
- **Severity:** Low
- **Criterion:** C-NamingConventions
- **Result:** Naming is generally consistent; constants could be more centralized.

4. **C-MagicNumbersStrings**
- **Severity:** Low  
- **Location:** Header names, paths, HTTP codes, port default.
- **Criterion:** C-MagicNumbersStrings
- **Remediation:** Introduce constants (`DEFAULT_PORT`, `HEADER_USER`, `HEADER_ROLES`, `PATH_VERSIONS`, etc.).

5. **C-ExceptionHandling**
- **Severity:** High  
- **Location:** `AppsHandler.handle()` catch-all and `handleRestore()` inner catch.
- **Criterion:** C-ExceptionHandling  
- **Issue:** Broad `catch (Exception e)` is used (acceptable for a top-level handler) but internal message is returned to client (also B-SensitiveDataExposure). Rollback catch also catches generic `Exception`.
- **Remediation:** Keep broad catch at boundary but return generic client messages; log server-side. Consider catching narrower exceptions where possible.

6. **C-NullSafety**
- **Severity:** Medium  
- **Location:** `handleGetVersions()` and `handleRestore()` accept `appId` from URL; no null/blank validation; headers sanitized only for blank user.
- **Criterion:** C-NullSafety
- **Remediation:** Validate `appId` against allowlist; reject blank/too-long values. Add checks for `parts[3]` and ensure `path.split("/")` yields expected segments.

7. **C-ResourceManagement**
- **Severity:** Low  
- **Location:** `readBody(HttpExchange exchange)`
- **Criterion:** C-ResourceManagement
- **Issue:** InputStream from `exchange.getRequestBody()` is read but not wrapped in try-with-resources. It may be closed by HttpExchange, but explicit closure is clearer.
- **Remediation:** Use `try (InputStream is = exchange.getRequestBody()) { ... }`.

8. **C-DuplicateCode**
- **Severity:** Low  
- **Location:** Repeated patterns: `writeJson(exchange, <status>, error(...))` and repeated authz guards.
- **Criterion:** C-DuplicateCode
- **Remediation:** Factor helper methods for common responses and for authorization gating.

9. **C-ThreadSafety**
- **Severity:** Medium  
- **Location:** `App.versions` is `HashMap`; GET reads without locking; restore writes under lock.
- **Criterion:** C-ThreadSafety
- **Issue:** Concurrent GET during restore may see inconsistent state (versions map swapped/cleared/putAll during rollback) since GET does not lock.
- **Remediation:** Use a concurrent/immutable snapshot for reads, or lock around both GET and restore operations for a consistent view. Alternatively store `versions` in `ConcurrentHashMap` and use immutable copy for iteration.
