### 2.2 Code Quality & Maintainability Findings

1. **Resource handling: `BufferedReader` not closed**
   - **Severity:** Low
   - **Location:** `RadioButtonTableApp.java` (method `main`, creation of `BufferedReader`)
   - **Issue:** `BufferedReader reader = new BufferedReader(...)` is not closed. While `System.in` is typically long-lived, in enterprise code and examples this is still flagged as a reliability/cleanliness concern.
   - **Remediation:** Use try-with-resources, or explicitly document why it is intentionally not closed.
     - Example:
       ```java
       try (BufferedReader reader = new BufferedReader(new InputStreamReader(System.in, StandardCharsets.UTF_8))) {
           ...
       }
       ```

2. **Console/log forging potential via untrusted `rowId` echoed to output**
   - **Severity:** Low
   - **Location:** `RadioButtonTableApp.java` (method `main`, branches printing `Selected: <rowId>` and validation error messages)
   - **Issue:** User-provided input (`rowId`) is printed directly. In console apps this is usually low impact, but when patterns are reused in services, logs can be manipulated with control characters (CRLF, ANSI escapes).
   - **Remediation:** Apply an allowlist for accepted IDs at the boundary (command parsing) and/or escape control characters before logging.
     - Example allowlist: `^[A-Za-z0-9_-]+$`

3. **Hard-coded radio group name can conflict in multi-component embedding**
   - **Severity:** Medium
   - **Location:** `RadioButtonTableApp.java` → `TableRow.radioGroupName()`
   - **Issue:** `radioGroupName()` always returns `"table-selection"`. If embedded into a UI with multiple tables/components, group names can collide causing incorrect selection behavior across tables.
   - **Remediation:** Make group name configurable per table instance (e.g., pass `groupName` into model, or expose it from the UI layer rather than `TableRow`).

4. **Nullable listener contract (`onSelectionChanged(null)` to indicate cleared)**
   - **Severity:** Low
   - **Location:** `RadioButtonTableApp.java` → `SelectionListener.onSelectionChanged(String selectedRowId)`
   - **Issue:** Null is used as a control signal. This increases risk of NPEs and ambiguous contracts in enterprise integrations.
   - **Remediation:** Prefer `Optional<String>` in callback, or split into `onSelected(String)` and `onCleared()`.

5. **Exception strategy inconsistency**
   - **Severity:** Low
   - **Location:** `TableRow.requireNonBlank()` throws `IllegalArgumentException`; selection normalization throws `ValidationException`.
   - **Issue:** Mixed exception types for validation may confuse API consumers.
   - **Remediation:** Standardize: either use `IllegalArgumentException` consistently or use `ValidationException` consistently and document it as part of the public API.

6. **Scalability: linear lookup for `findRow()`**
   - **Severity:** Low
   - **Location:** `SelectionModel.findRow()`
   - **Issue:** O(n) search per selection. For very large tables, this may impact responsiveness.
   - **Remediation:** Maintain an index (e.g., `Map<String, TableRow>`) for O(1) lookups while preserving list order for rendering.
