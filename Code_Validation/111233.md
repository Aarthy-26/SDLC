### B. Security (OWASP Top 10 mapping — explicit)

#### B-Injection
- **Finding:** Low risk. SQL queries use `JdbcTemplate` parameter binding (`?`) and do **not** concatenate inputs into SQL.
- **Status:** PASS

#### B-BrokenAuthentication
- **Finding:** Potential trust-boundary issue: endpoint accepts `username`/`email` directly from request body; no binding to authenticated SSO principal.
- **Status:** FAIL (design-level authN gap)

**Issue**
2. Trust boundary / Broken Authentication risk: request-body identity can be spoofed
   - **Severity:** High
   - **Location:** `SsoProvisioningController.resolveOrProvision(...)`
   - **Criterion:** B-BrokenAuthentication
   - **Remediation:**
     - Enforce Spring Security so endpoint is callable only after verified IdP authentication.
     - Derive `username/email` from validated IdP claims (OIDC `id_token` / `Authentication` principal), not from JSON body.
     - Require token expiry and issuer/audience validation at gateway/security filter.

#### B-SensitiveDataExposure
- **Finding:** Response returns `UserModel` directly; may include sensitive fields (e.g., `password`) depending on `UserModel` JSON serialization.
- **Status:** FAIL (possible exposure)

**Issue**
3. Potential sensitive data exposure via returning `UserModel`
   - **Severity:** Medium
   - **Location:** `SsoProvisioningController.resolveOrProvision(...)`
   - **Criterion:** B-SensitiveDataExposure
   - **Remediation:** Return a dedicated DTO that excludes secret fields (password hash, internal flags). Ensure `UserModel.password` is `@JsonIgnore` if `UserModel` must be reused.

#### B-XXE
- **Finding:** No XML parsing.
- **Status:** PASS

#### B-BrokenAccessControl
- **Finding:** Endpoint provisions users (data mutation / identity operation) without explicit authorization checks.
- **Status:** FAIL

**Issue**
4. Broken access control: provisioning endpoint lacks authorization guardrails
   - **Severity:** High
   - **Location:** `@PostMapping("/sso/resolve-user")`
   - **Criterion:** B-BrokenAccessControl
   - **Remediation:**
     - Restrict endpoint to authenticated SSO context (e.g., `@PreAuthorize("isAuthenticated() && hasAuthority('SSO_AUTHENTICATED')")` or equivalent).
     - Add CSRF protections where applicable.
     - Consider rate limiting and abuse protection for provisioning endpoint.

#### B-SecurityMisconfiguration
- **Finding:** Unhandled exceptions (`IllegalArgumentException`, `IllegalStateException`) will rely on global defaults; may result in verbose errors/stack traces depending on Spring configuration.
- **Status:** PARTIAL

**Issue**
5. Missing centralized exception handling for consistent/safe API responses
   - **Severity:** Medium
   - **Location:** Controller/service exception paths
   - **Criterion:** B-SecurityMisconfiguration
   - **Remediation:** Add `@ControllerAdvice` to map:
     - validation errors → 400 with sanitized messages
     - unexpected errors → 500 generic message
     - ensure stack traces are not returned to clients.

#### B-XSS

- **Status:** PASS

#### B-InsufficientLogging&Monitoring
- **Finding:** No audit logs for provisioning (identity lifecycle event).
- **Status:** FAIL

**Issue**
6. Missing audit logging for sensitive identity operation
   - **Severity:** Medium
   - **Location:** `SsoUserProvisioningService.resolveOrProvisionUser(...)`
   - **Criterion:** B-InsufficientLogging&Monitoring
   - **Remediation:** Add SLF4J structured audit logs for:
     - attempt (with correlation id)

#### Additional security concern (OWASP-aligned): account linking
- **Finding:** Email fallback can link an SSO login to an existing account purely by email.

**Issue**
7. Account linking/takeover risk due to email fallback
   - **Severity:** High
   - **Location:** `SsoUserProvisioningService.resolveOrProvisionUser(...)` → `findByEmailIgnoreCase(...)`
   - **Criterion:** B-BrokenAccessControl (identity integrity)
   - **Remediation:**
     - Prefer immutable IdP identifiers: `(issuer, subject)`.
     - Only allow email fallback if `email_verified=true` and tenant/issuer matches.
     - Consider explicit user-driven linking flow.

### C. Code Quality & Maintainability

**Issues**
8. Null-safety gap: controller can throw NPE when request body is null
   - **Severity:** Low
   - **Location:** `SsoProvisioningController.resolveOrProvision(...)`
   - **Criterion:** C-NullSafety
   - **Remediation:** Guard `request == null` and/or use Bean Validation:
     - `public ResponseEntity<ApiResponse<UserDto>> resolveOrProvision(@Valid @RequestBody SsoLoginRequest request)`
     - Add `@NotBlank` on fields and `@Validated`.

9. Integrity exception retry may mask non-duplicate integrity violations
   - **Severity:** Medium
   - **Location:** `catch (DataIntegrityViolationException dup)` block
   - **Criterion:** C-ExceptionHandling
   - **Remediation:** Check SQLState/constraint name to ensure it’s the expected uniqueness violation before retry; otherwise rethrow/wrap.

10. Use of `SELECT *` increases coupling and may pull sensitive columns
   - **Severity:** Low
   - **Location:** `SsoUserRepository.findByUsername/findByEmailIgnoreCase/findById`
   - **Criterion:** C-CodeQuality
   - **Remediation:** Select explicit columns required by mapper (e.g., `id, username, password, email, enabled, created_at`).
