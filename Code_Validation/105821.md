## 3) Code Quality & Maintainability (C)

### Complexity / size checks
- **Cyclomatic complexity**: No method appears to exceed **>10** materially; the most complex is `ColumnNamingStrategy.toSnake` and `EntitySourceScanner.scanFile`, but both are still manageable.
- **Method length**: No method observed > 50 lines except potentially `toSnake` and `scanFile` depending on formatting; still close to threshold.
- **Class length**: ~400 lines; under 500 threshold.

### Findings
1. **Regex-based parsing is brittle for real Java source**
   - **Severity**: Medium
   - **Location**: `EntitySourceScanner.scanFile` patterns
   - **Criterion**: C-CodeQuality
   - **Details**: Scanner only matches `@Column(...)` when annotation closes on the same line and field declaration matches a limited pattern. Multiline annotations, record components, Lombok, annotations on getters, or fields split across lines may be missed.
   - **Remediation**: Replace regex parsing with an AST parser (JavaParser/Eclipse JDT). If staying regex-based, document limitations and add extensive tests.

2. **Atomic move portability gap**
   - **Severity**: Low
   - **Location**: `EntitySourceRewriter.rewriteFile`
   - **Criterion**: C-ResourceManagement
   - **Details**: `ATOMIC_MOVE` may fail across filesystems. Current code does not catch `AtomicMoveNotSupportedException` and fallback; it will throw.
   - **Remediation**: Catch `AtomicMoveNotSupportedException` and fallback to `REPLACE_EXISTING`.

3. **Backup overwrite risk**
   - **Severity**: Medium
   - **Location**: `EntitySourceRewriter.rewriteFile` creates `*.bak`
   - **Criterion**: C-CodeQuality
   - **Details**: Repeated runs overwrite `.bak`, weakening rollback evidence.
   - **Remediation**: Use timestamped backups or a dedicated backup directory; refuse overwrite unless `--force`.

4. **Unused imports**
   - **Severity**: Low
   - **Location**: `Code_Output/105821.java`
   - **Criterion**: C-CodeQuality
   - **Remediation**: Remove unused imports.

5. **Null-safety**
   - **Severity**: Low
   - **Location**: `CliConfig.parse(String[] args)`
   - **Criterion**: C-NullSafety
   - **Details**: `args` may be null (depending on invocation); loop uses `args.length` → NPE.
   - **Remediation**: Guard `if (args == null) args = new String[0];` or throw a friendly ToolException.
