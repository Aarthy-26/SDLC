## C. Code Quality & Maintainability
**Status: Generally good; some robustness gaps.**

### Issues Found
5. **Validator may miss mappings due to field-only reflection (property access not covered)**
   - Severity: **Medium**
   - Location: `EntityColumnMappingValidator.resolveColumnName()`
   - Criterion: **C-NullSafety / C-CodeQuality**
   - Details: Uses `getDeclaredField(attr.getName())`. If JPA uses property access (`@Access(PROPERTY)`) or attributes are exposed via getters only, validator will skip (NoSuchFieldException) and not validate the mapping.
   - Remediation:
     - Support property access via `Introspector` / getter reflection, or
     - Enforce `@Access(AccessType.FIELD)` on entities in this module and validate that constraint.

6. **Validation is “explicit @Column only”; unannotated persistent fields are skipped**
   - Severity: **Medium**
   - Location: `EntityColumnMappingValidator.resolveColumnName()`
   - Criterion: **C-CodeQuality**
   - Details: If an entity has a persistent basic field without `@Column`, validator ignores it, allowing drift to slip through.
   - Remediation (pick one policy and enforce it):
     - Fail if a basic attribute lacks `@Column` (strong enterprise standard), OR
     - Compute expected physical column using the configured naming strategy and validate it too.

7. **Embedded attributes / attribute overrides not handled (possible false negatives)**
   - Severity: **Medium**
   - Location: `validateAllEntities()` attribute iteration
   - Criterion: **C-CodeQuality**
   - Details: Comment says “validate basic + embedded columns” but code does not traverse embedded/overrides; `attr.isAssociation()`/`isCollection()` skip associations but embedded needs special handling.
   - Remediation: Detect embedded attributes and validate overridden column names (`@AttributeOverride(s)`), or explicitly document as out-of-scope.

8. **Regex-based snake_case conversion may be inefficient and has edge-case risks**
   - Severity: **Low**
   - Location: `AavaPhysicalNamingStrategy.toSnakeCase()`
   - Criterion: **C-CodeQuality**
   - Details: Multiple `replaceAll` calls per invocation. Could be acceptable but may be optimized.
   - Remediation: Precompile patterns or implement single-pass conversion; add unit tests for acronyms/digits/edge cases.

9. **Entity constructors do not validate invariants (null/blank fields)**
   - Severity: **Low**
   - Location: `CustomerEntity`, `OrderEntity` constructors
   - Criterion: **C-NullSafety**
   - Details: Constructor accepts nulls; downstream failures possible.
   - Remediation: Add `Objects.requireNonNull` checks (mind JPA constraints) or validate at service layer.

Complexity/size:
- Cyclomatic complexity: No method appears > 10 (largest is `validateAllEntities`, still moderate).
- Method length: All methods appear < 50 lines; class sizes well below thresholds.
