## Issues Found

### 1) Missing authorization checks on endpoints
- **Severity**: Critical
- **Location**: `ApiController.java` (class `ApiController`, endpoints `/api/apps`, `/api/projects/{id}/details`)
- **Criterion**: B-BrokenAccessControl
- **Why**: Endpoints are unauthenticated/unauthorized; story context references project/app details which can be sensitive. There are no annotations/guards (e.g., Spring Security `@PreAuthorize`, authentication filters).
- **Remediation**:
  - Add Spring Security and enforce authentication.
  - Add role/permission checks for each endpoint, e.g. `@PreAuthorize("hasAuthority('APPS_READ')")`.
  - Add security tests verifying 401/403 behavior.

### 2) Actuator endpoints exposed broadly (potential information disclosure)
- **Severity**: High
- **Location**: `application.properties` (`management.endpoints.web.exposure.include=health,info,metrics,prometheus`)
- **Criterion**: B-SecurityMisconfiguration
- **Why**: Exposing `metrics` and `prometheus` without access control can leak operational information and potentially identifiers.
- **Remediation**:
  - Restrict actuator exposure in production (separate management port / network ACLs).
  - Protect actuator endpoints via Spring Security.
  - Consider disabling `info/metrics/prometheus` by default and enabling via profile.

### 3) Error handling may leak internal exception messages for bad requests
- **Severity**: High
- **Location**: `GlobalExceptionHandler.java`, method `handleBadRequest(Exception ex, ...)`
- **Criterion**: B-SecurityMisconfiguration
- **Why**: Returning `ex.getMessage()` to clients can reveal internal details (parameter names, stack context from some exceptions).
- **Remediation**:
  - Return a sanitized, client-safe message for 400s, and log full details server-side.
  - Map `ConstraintViolationException` and `MethodArgumentNotValidException` to structured validation errors.

### 4) Potential Denial-of-Service via ArithmeticException on extreme pagination
- **Severity**: Medium
- **Location**: `AppService.java`, method `getApps(int page, int size)` uses `Math.multiplyExact(page, size)`
- **Criterion**: C-NullSafety (validated inputs) / C-CodeQuality (robustness)
- **Why**: With `page=Integer.MAX_VALUE`, multiplication overflows and throws `ArithmeticException`. This becomes a 500 (server error) and could be used for noisy error generation.
- **Remediation**:
  - Guard against overflow: use `long fromL = (long) page * (long) size; if (fromL > Integer.MAX_VALUE) return List.of();`.
  - Or cap `page` via validation (`@Max`) in controller.
  - Add explicit exception mapping for `ArithmeticException` to 400.

### 5) Cache does not specify behavior for null loader results
- **Severity**: Medium
- **Location**: `TtlCache.java`, method `get(K key, Supplier<V> loader)`
- **Criterion**: C-NullSafety
- **Why**: If `loader.get()` returns null, cache stores `CacheEntry<>(null, ...)` and later `updated.value()` can lead to downstream NPEs. Unit test inventory explicitly documents current NPE behavior.
- **Remediation**:
  - Enforce non-null values: `V loaded = Objects.requireNonNull(loader.get(), "loader returned null")`.
  - Or allow nulls explicitly by using `Optional<V>` values.
  - Add tests asserting chosen behavior.

### 6) Insufficient audit logging for critical operations
- **Severity**: Medium
- **Location**: `ApiController.java`, `AppService.java`, `ProjectService.java`
- **Criterion**: B-InsufficientLogging&Monitoring
- **Why**: Reads of potentially sensitive project/app data have no structured audit logs (who, what, when). Micrometer timers help performance monitoring but not audit trails.
- **Remediation**:
  - Add structured logs with request identifiers and principal/user id (once auth is implemented).
  - Add an audit logger for access to `/api/projects/{id}/details`.

### 7) Use of Lombok dependency without usage and potential policy constraints
- **Severity**: Low
- **Location**: `pom.xml` includes Lombok
- **Criterion**: E-EnterpriseCompliance (components/policy alignment)
- **Why**: Lombok is optional but not used in shown code; some enterprises restrict Lombok.
- **Remediation**:
  - Remove Lombok dependency if not needed.
  - If needed, document/approve via SDLC policy.

### 8) License header missing (org-template dependent)
- **Severity**: Medium
- **Location**: All Java files shown
- **Criterion**: E-LicenseHeader
- **Why**: No license/copyright headers present. Requirement says “if org template requires one”.
- **Remediation**:
