## Issues Found

### 1) Unbounded cache growth for per-project cache (potential memory/DoS risk)
- **Severity:** Medium
- **Location:** `src/main/java/com/aava/datastudio/service/ProjectService.java` (cache field `projectDetailsCache`), `src/main/java/com/aava/datastudio/service/cache/TtlCache.java`
- **Details:** `projectDetailsCache` is keyed by project id. With many unique ids over time, the in-memory map can grow without bound. TTL expiration alone does not remove entries until they are accessed again; stale entries remain resident.
- **Remediation:**
  - Prefer a proven cache implementation (e.g., Caffeine) with `maximumSize`, `expireAfterWrite`, and optional stats.
  - If staying dependency-free, implement: max entries + eviction strategy (LRU-ish), and/or a periodic cleanup job to remove expired entries.
  - Add operational protections: request rate limiting, input constraints on `id`.

### 2) TTL cache null-handling can cause runtime NPE
- **Severity:** Medium
- **Location:** `src/main/java/com/aava/datastudio/service/cache/TtlCache.java` method `get(K key, Supplier<V> loader)`
- **Details:** If `loader.get()` returns `null`, `updated.value()` will throw `NullPointerException` when returned. This is already captured by unit test case **#26** as an observed negative behavior.
- **Remediation:**
  - Enforce non-null values: `V loaded = Objects.requireNonNull(loader.get(), "loader returned null");`.
  - Or cache `Optional<V>` to represent absence safely.
  - Document cache contract explicitly in Javadoc.

### 3) Pagination overflow yields 500 (ArithmeticException not mapped to 400)
- **Severity:** Medium
- **Location:** `src/main/java/com/aava/datastudio/service/AppService.java` method `getApps(int page, int size)`
- **Details:** `Math.multiplyExact(page, size)` can throw `ArithmeticException` for extreme `page` values. Current `GlobalExceptionHandler` does **not** map `ArithmeticException` to 400, so this becomes a 500.
- **Evidence in tests:** Unit test case **#35** expects `ArithmeticException` at service-level; no controller test validates HTTP mapping.
- **Remediation:**
  - Add controller validation constraint on `page` (e.g., `@Max(...)`) appropriate to business limits.
  - Handle overflow explicitly and map to `IllegalArgumentException` / 400.
  - Or add `@ExceptionHandler(ArithmeticException.class)` mapping to 400.

### 4) Exception handler leaks raw exception messages to clients
- **Severity:** Medium
- **Location:** `src/main/java/com/aava/datastudio/exception/GlobalExceptionHandler.java` method `handleBadRequest(...)` and `handleNotFound(...)`
- **Details:** Returning `ex.getMessage()` can disclose internal details or identifiers as the code evolves. Current messages include `Project not found for id=...`.
- **Remediation:**
  - Return standardized, user-safe messages and include a correlation id.
  - For validation errors, return a structured error list (field -> message) rather than raw exception text.
  - Log server-side details at appropriate level with redaction.

### 5) Missing controller-layer bean validation for path variable `id`
- **Severity:** Low
- **Location:** `src/main/java/com/aava/datastudio/api/ApiController.java` method `getProjectDetails(@PathVariable("id") long id)`
- **Details:** `id` is validated in the service layer only. Controller-level validation (e.g., `@Min(1)`) would provide earlier rejection and consistent constraint violation handling.
- **Remediation:**
  - Add `@Min(1)` to the `@PathVariable` parameter and keep service check as defense-in-depth.

### 6) Operational security: actuator endpoints exposed without access controls mentioned
- **Severity:** Medium
- **Location:** `src/main/resources/application.properties`
- **Details:** `management.endpoints.web.exposure.include=health,info,metrics,prometheus` exposes operational metrics endpoints. In many enterprises, these must be restricted (network, authn/z, separate port).
- **Remediation:**
  - Bind actuator to a separate management port and restrict via network policy.
  - Add authentication/authorization (Spring Security) for non-public actuator endpoints.
  - Ensure Prometheus scraping is restricted and does not expose sensitive tags.

### 7) Observability improvement: timers lack tags and distribution configuration
- **Severity:** Low
- **Location:** `src/main/java/com/aava/datastudio/service/AppService.java`, `src/main/java/com/aava/datastudio/service/ProjectService.java`
- **Details:** Timers are created but without useful tags (endpoint, outcome) and without percentile/histogram configuration.
- **Remediation:**
  - Add tags and/or use `@Timed` for standardization.
  - Configure `management.metrics.distribution.percentiles-histogram.*` as needed.
