## B. Security (OWASP Top 10 mapping)
### B-Injection
- **Finding:** No SQL injection risk from user-controlled concatenation.
  - `SmokeTester` executes constant query `"SELECT 1"` with `PreparedStatement`.
  - **Status:** No issue.

### B-BrokenAuthentication
- **Finding:** No hardcoded credentials. Secrets sourced from properties or environment.
  - **Status:** No issue.
  - **Note:** The main method defaults `DPAI_ENV=dev` and `DPAI_CONFIG_DIR=./config` if unset. That is not “authentication” but can affect operational security (see E-ConfigExternalization below).

### B-SensitiveDataExposure
1. **Risk of credential exposure through Java Util Logging exception logging**
   - **Severity:** High
   - **Location:** `DpaiAavaDataSourceApp.main()` catches `DpaiConfigException` and `DpaiDataSourceException` and logs with throwable
   - **Criterion:** B-SensitiveDataExposure
   - **Details:** `log.log(Level.SEVERE, "..." , e)` will include stack trace. Upstream `SQLException` messages can sometimes include usernames/URLs and, in some drivers/misconfigurations, sensitive fragments.
   - **Remediation:**
     - Log a sanitized message for expected failures; consider logging stack traces only at DEBUG for non-prod.
     - Ensure JDBC URLs do not embed secrets.

2. **Secret stored as immutable `String` in memory**
   - **Severity:** Medium
   - **Location:** `DbConfig.secret` and `SimpleDriverManagerDataSource.secret`
   - **Criterion:** B-SensitiveDataExposure
   - **Details:** Secrets stored as `String` cannot be zeroed; increases exposure via heap dumps.
   - **Remediation:** Prefer `char[]` where practical, or isolate secrets in a dedicated credential provider. If retaining `String`, document operational controls (heap dump access restrictions).
