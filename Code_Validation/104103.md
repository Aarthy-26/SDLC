## A. Syntax & Compilation

### Findings
1. **Duplicate YAML key `spring:` in `application.yml` may override earlier block**
   - **Severity**: Medium
   - **Location**: `src/main/resources/application.yml` (two top-level `spring:` blocks)
   - **Criterion**: A-Syntax&Compilation
   - **Why it matters**: YAML parsers can treat duplicate keys as “last wins”, potentially dropping `spring.application.name` or profile defaults depending on parser behavior.
   - **Remediation**: Merge into one block:
     ```yaml
     spring:
       application:
         name: dpai-aava-datasource
       profiles:
         default: dev
     ```

2. **No deprecated APIs detected**

   - **Location**: N/A

## B. Security (OWASP Top 10 mapping)

> Note: This assessment is based on provided source snippets only (no runtime config/infra). Each item is explicitly checked per criteria.

1. **B-Injection**: **No injection risk identified in provided code**
   - `DbHealthController` uses `PreparedStatement` with constant query `"SELECT 1"`.

2. **B-BrokenAuthentication**: **Potential exposure if `/api/db/health` is publicly reachable**
   - **Severity**: Medium
   - **Location**: `DbHealthController` endpoint `/api/db/health`
   - **Criterion**: B-BrokenAuthentication / B-BrokenAccessControl (see next)
   - **Why it matters**: Health endpoints can be used for reconnaissance (service existence, availability). Even with sanitized output, it confirms DB reachability.
   - **Remediation**: Restrict endpoint access:
     - Prefer Spring Actuator `/actuator/health` with security rules.
     - Or apply authN/authZ (Spring Security) and/or network-level restrictions.

3. **B-SensitiveDataExposure**: **Partially mitigated, but missing internal logging/audit trail**
   - **Severity**: Medium
   - **Location**: `DbHealthController.health()`
   - **Criterion**: B-SensitiveDataExposure / B-InsufficientLogging&Monitoring
   - **Why it matters**: Client response is sanitized (good), but lack of internal logs reduces incident response and auditability.
   - **Remediation**:
     - Log failures internally using SLF4J with sanitized fields only (no JDBC URL/password/token).
     - Include request/correlation id.

5. **B-BrokenAccessControl**: **No authorization check shown for health endpoint**
