User Story ID: 104103
Review Summary: Overall, the implementation is production-leaning and security-conscious (redacts secrets, uses try-with-resources, typed exceptions, and PreparedStatement). Code quality is strong and meets most enterprise standards. Primary gaps are (1) single-file multi-class design increasing maintenance risk and trending toward a “God class” pattern, (2) logging framework choice (java.util.logging vs SLF4J) depending on internal standards, (3) insufficient input hardening for env/config path usage (potential path manipulation), and (4) lack of explicit TLS/encryption-at-rest/retention controls and audit-event schema for SOC2/PCI narratives.

Findings:
Issue: Single-file “multi-class” design increases coupling and maintainability risk (God Class trend)
Severity: Medium
Recommendation: Split nested classes into separate files/packages aligned to layered structure (e.g., config, provider/bridge, datasource, cli). Keep DpaiAavaDataSourceApp as thin CLI entrypoint. Add unit tests per class.
Compliance Impact: SOC2 (Maintainability/Change management) – indirect; increases risk of defects and insufficient separation of duties.

Issue: Path handling for DPAI_CONFIG_DIR + DPAI_ENV can be abused (path traversal / unintended file read)
Severity: High
Recommendation: Canonicalize and constrain config path. Validate env against an allow-list regex (e.g., ^[a-zA-Z0-9_-]+$) and prohibit path separators. Resolve canonical path for configDir and ensure the resolved target file stays within configDir. Consider using java.nio.file.Path normalize/resolve and deny .. segments.
Compliance Impact: SOC2 (Security) – unauthorized configuration disclosure risk; PCI-DSS if config can contain cardholder-related secrets/keys.

Issue: Uses java.util.logging instead of approved enterprise logging façade (often SLF4J)
Severity: Low
Recommendation: If enterprise standard mandates SLF4J/Logback, switch to SLF4J and enforce structured logging (key=value) with consistent event IDs.
Compliance Impact: SOC2 (Audit logging consistency) – low; mainly operational consistency.

Issue: Potential sensitive information exposure via exception logging stack traces in CLI
Severity: Medium
Recommendation: For CLI this may be acceptable, but for any service context avoid logging full stack traces at SEVERE unless protected. Consider logging a sanitized message with correlationId and keeping stack traces behind debug logs or secure sinks.
Compliance Impact: SOC2 – may expose internal details; PCI-DSS if stack traces include sensitive connection details.

Issue: DbConfig exposes secret via getter (secret()) increasing accidental leakage risk
Severity: Medium
Recommendation: Avoid exposing secret() publicly; pass secret only to provider creation. Consider storing secret as char[] and zeroing after use where feasible (not perfect in JVM but reduces risk). Provide only redacted views.
Compliance Impact: SOC2/PCI-DSS – reduces risk of secret leakage; supports least exposure.

Issue: AuthMode is parsed but not enforced/used to change behavior (PASSWORD vs TOKEN)
Severity: Low
Recommendation: Either (a) implement distinct handling (e.g., different property key names, different JDBC properties, or provider-specific logic), or (b) remove until needed to avoid misleading configuration.
Compliance Impact: Internal policy (configuration correctness) – low.

Issue: DriverManager.setLoginTimeout is global JVM state (side effect / concurrency risk)
Severity: Medium
Recommendation: Prefer per-DataSource timeouts where supported (driver-specific properties) or synchronize/avoid mutating global DriverManager state. At minimum, document behavior.
Compliance Impact: SOC2 (Reliability/Availability) – could impact other components in same JVM.

Issue: Default env fallback to "dev" may be unsafe in production automation
Severity: Medium
Recommendation: In production mode, require DPAI_ENV explicitly; or fail fast if not set. Alternatively, allow default only when an explicit "--allowDefaultEnv" flag is provided.
Compliance Impact: SOC2 (Change management/config management) – misconfiguration risk.

Issue: Lack of explicit network encryption/TLS enforcement checks for JDBC URL
Severity: Medium
Recommendation: Validate JDBC URL requires TLS where applicable (e.g., verify sslMode=require / encrypt=true settings depending on vendor). Document required parameters per DB.
Compliance Impact: PCI-DSS (encryption in transit) – may be unmet if TLS not enforced; SOC2 (Security).

Issue: No explicit audit-event logging for sensitive operations (config load, DS creation, connection test)
Severity: Medium
Recommendation: Add explicit audit events with event IDs, actor/context (env, correlationId), and outcome (success/failure), ensuring no secrets. Consider an AuditLogger interface.
Compliance Impact: SOC2 – auditability gap.
