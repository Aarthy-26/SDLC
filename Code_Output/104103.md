User Story ID: 104103

1. **Requirement Summary**

Implement and integrate an AAVA-provided DataSource connection management library into the DPAI application so that DPAI does not implement its own database connection/credential handling. DPAI must load environment-specific configuration for JDBC URL, username, authentication mode, and other required properties, and establish the DataSource via the AAVA Library.

Assumptions (enterprise defaults applied due to missing specifics in the story):
- Java 17.
- Spring Boot 3.3.x application.
- Maven build.
- The “AAVA Library” is represented by an integration adapter (`AavaDataSourceFactory`) that builds a pooled `DataSource` from strongly-validated configuration. In a real project this class would be replaced by the vendor-provided AAVA library dependency and its builder/factory API; the code is structured to make that swap minimal.
- Authentication modes supported: `BASIC` (username/password via env vars) and `IAM` (token/opaque string via env vars). Secrets are read from environment variables only; no secrets are stored in source or application properties.
- Environment-specific configuration is done via Spring profiles (`application-dev.yml`, `application-qa.yml`, `application-prod.yml`), while secrets come from environment variables.
- Demonstration includes a health endpoint that validates DataSource connectivity via a simple `SELECT 1` (works for most RDBMS; adjust if needed).

package com.dpai.aava.security;

import java.util.Objects;

/**
 * Provides secret values from a secure source.
 *
 * Default implementation reads from environment variables only to avoid committing secrets to config files.
 */
public interface SecretProvider {

    /**
     * Returns an environment variable value.
     *
     * @param name environment variable name
     * @return value
     * @throws SecretNotFoundException if missing or blank
     */
    String requiredEnv(String name);

    /**
     * Default env-based provider.
     */
    static SecretProvider env() {
        return new EnvSecretProvider();
    }

    /**
     * Env-backed implementation.
     */
    final class EnvSecretProvider implements SecretProvider {
        @Override
        public String requiredEnv(String name) {
            Objects.requireNonNull(name, "name");
            String value = System.getenv(name);
            if (value == null || value.isBlank()) {
                throw new SecretNotFoundException("Missing required environment variable: " + name);
            }
            return value;
        }
    }
}

// src/main/java/com/dpai/aava/integration/AavaDataSourceFactory.java
package com.dpai.aava.integration;

import com.dpai.aava.config.AavaDataSourceProperties;
import com.dpai.aava.config.AavaDataSourceProperties.AuthMode;
import com.dpai.aava.security.SecretProvider;
import com.zaxxer.hikari.HikariConfig;
import com.zaxxer.hikari.HikariDataSource;

import javax.sql.DataSource;
import java.util.Objects;

/**
 * Adapter/factory that represents the AAVA Library entry point for creating a DataSource.
 *
 * Replace this class with the real AAVA library dependency and API when available.
 * The rest of the application should remain unchanged.
 */
public final class AavaDataSourceFactory {

    private AavaDataSourceFactory() {
    }

    /**
     * Builds a pooled {@link DataSource} using validated properties and env-provided secrets.
     *
     * Supported auth modes:
     * - BASIC: requires env var AAVA_DB_PASSWORD
     * - IAM:   requires env var AAVA_DB_IAM_TOKEN (treated as password/token for driver)
     */
    public static DataSource create(AavaDataSourceProperties props, SecretProvider secrets) {
        Objects.requireNonNull(props, "props");
        Objects.requireNonNull(secrets, "secrets");

        String passwordOrToken = switch (props.getAuthMode()) {
            case BASIC -> secrets.requiredEnv("AAVA_DB_PASSWORD");
            case IAM -> secrets.requiredEnv("AAVA_DB_IAM_TOKEN");
        };

        // Hikari used as an enterprise-standard pool; the AAVA library may wrap/configure this similarly.
        HikariConfig cfg = new HikariConfig();
        cfg.setJdbcUrl(props.getJdbcUrl());
        cfg.setUsername(props.getUsername());
        cfg.setPassword(passwordOrToken);

        cfg.setMaximumPoolSize(props.getPool().getMaxPoolSize());
        cfg.setMinimumIdle(props.getPool().getMinIdle());
        cfg.setConnectionTimeout(props.getPool().getConnectionTimeoutMs());
        cfg.setIdleTimeout(props.getPool().getIdleTimeoutMs());
        cfg.setMaxLifetime(props.getPool().getMaxLifetimeMs());

        // Security/robustness defaults
        cfg.setAutoCommit(true);
        cfg.setPoolName("dpai-aava-pool");

        // Fail fast if misconfigured (0 = don't fail fast). Keep modest to surface config issues early.
        cfg.setInitializationFailTimeout(10_000);

        return new HikariDataSource(cfg);
    }
}

package com.dpai.aava.config;

import com.dpai.aava.integration.AavaDataSourceFactory;
import com.dpai.aava.security.SecretProvider;

import javax.sql.DataSource;

import org.springframework.boot.context.properties.EnableConfigurationProperties;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;

/**
 * Spring configuration that wires the application's {@link DataSource} via the AAVA Library adapter.
 */
@Configuration
@EnableConfigurationProperties(AavaDataSourceProperties.class)
public class DataSourceConfiguration {

    @Bean
    public SecretProvider secretProvider() {
        return SecretProvider.env();
    }

    @Bean
    public DataSource dataSource(AavaDataSourceProperties props, SecretProvider secretProvider) {
        return AavaDataSourceFactory.create(props, secretProvider);
    }
}

package com.dpai.api;

import jakarta.servlet.http.HttpServletRequest;

import org.springframework.http.HttpStatus;
import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RestController;

import javax.sql.DataSource;
import java.sql.Connection;
import java.sql.PreparedStatement;
import java.sql.ResultSet;
import java.time.OffsetDateTime;
import java.util.LinkedHashMap;
import java.util.Map;

/**
 * Simple endpoint to validate that the AAVA-managed DataSource can obtain a connection.
 */
@RestController
@RequestMapping("/api")
public class DbHealthController {

    private final DataSource dataSource;

    public DbHealthController(DataSource dataSource) {
        this.dataSource = dataSource;
    }

    @GetMapping("/db/health")
    public ResponseEntity<Map<String, Object>> health(HttpServletRequest request) {
        Map<String, Object> body = new LinkedHashMap<>();
        body.put("path", request.getRequestURI());
        body.put("timestamp", OffsetDateTime.now().toString());

        try (Connection c = dataSource.getConnection();
             PreparedStatement ps = c.prepareStatement("SELECT 1");
             ResultSet rs = ps.executeQuery()) {

            boolean ok = rs.next();
            body.put("dbConnected", ok);
            return ResponseEntity.ok(body);

        } catch (Exception ex) {
            // Do not leak credentials or detailed connection strings.
            body.put("dbConnected", false);
            body.put("error", "Database connectivity check failed");
            return ResponseEntity.status(HttpStatus.SERVICE_UNAVAILABLE).body(body);
        }
    }
}

3. **Code Documentation**

- `AavaDataSourceProperties`: Validated configuration model loaded from environment-specific Spring profiles. Ensures JDBC URL, username, authMode, and pool settings are present and sane.
- `SecretProvider` + `SecretNotFoundException`: Enforces that secrets (password/token) come from environment variables only; missing secrets fail fast.
- `AavaDataSourceFactory`: Represents the AAVA Library integration point. Builds a pooled `DataSource` (HikariCP) using the configured auth mode and secrets. This is the only component that should change when swapping to the real AAVA library.
- `DataSourceConfiguration`: Wires the application’s `DataSource` bean via the AAVA factory; DPAI code never creates connections directly.
- `DbHealthController`: Provides a simple endpoint to verify DataSource connectivity without leaking sensitive details.
